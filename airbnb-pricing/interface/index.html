How it was built

One pipeline, eight stages

Each stage feeds the next, and each decision was tested on hosts the model had never seen. The numbers on each stage are the evidence behind it.

    Stage 1

    Data

    The question is a regression problem: predict a nightly price from what a host knows about the listing. Everything comes from public sources, joined by listing ID, neighbourhood and date.

    Stage 3

    Build features, then screen them

    Candidates were ranked against price, checked for redundancy and for leakage, and then each new idea was added to the model on its own. An idea was kept only if it lowered the error on unseen hosts in at least 4 of 5 folds.

    Which listing basics relate to price

    Spearman captures steady up-or-down relationships; mutual information captures any shape. Crossed-out variables were dropped or replaced.

    What the final model reads

    141 features in eight families. Share of the final model's split gain.

    • Listing basics: room type, minimum nights, reviews, license, host size band, neighbourhood, coordinates, title keywords
    • Detailed attributes: guests, bedrooms, beds, bathrooms (shared or private), 12 property groups, 30 amenity groups, 7 review scores, superhost
    • Location context: distance to 14 demand drivers, listings within 300 m and 1 km, 8 zones
    • Time: season, quarters live, days since the last review, months since the first review, night of the week priced

    Stage 4

    Compare model types

    Each method makes a different assumption about how price relates to the features. All were trained on the same 141 features and scored on the same unseen hosts.

    Rule of thumb

    Median price of listings with the same neighbourhood and room type. Every model has to beat it.

    Linear, ridge, Lasso

    Price as a weighted sum of features. Ridge and Lasso shrink weights; Lasso can set them to zero. Clear, but no interactions.

    Decision tree (CART)

    One tree of yes/no questions. Easy to read, but unstable and quick to overfit.

    Random forest

    Hundreds of trees on random samples, averaged. Robust, captures interactions.

    Gradient boosting

    Small trees built in sequence, each fixing the last one's errors. LightGBM and CatBoost are fast versions.

    Neural network

    A multilayer perceptron: layers of weighted sums with non-linear steps, trained by gradient descent.

    Stage 5

    Test the way the tool will be used

    Large hosts run up to 87 listings with similar pricing. A random split puts some of a host's listings in training and the rest in test, so the model partly remembers the host. A new user is always a new host, so every result on this page splits by host.

    What the honest test changed

    • Every model loses R² on average under the host split.
    • The host's listing count acted as a host fingerprint (highest mutual information, near-zero correlation). It was replaced by five size bands.
    • Days until the quoted night lowered the error more than any feature, but it measures how booked-up a listing is, a result of its price. It was excluded.
    • Listings without reviews stay in the data: a pricing tool has to serve new hosts.

    Stage 7

    Richer data, then neural networks for text and photos

    The whole improvement path, replayed on one setup: LightGBM, 7,039 listings, host-grouped 5-fold CV. Each rung adds one group of inputs to everything above it.

    The ladder

    Cross-validated error per night. Lower is better.

    How the neural networks are used

    1. Read. bge-small-en-v1.5 (33M parameters) turns each description, and the 30 most recent reviews, into 384 numbers. CLIP ViT-B/32 turns the cover photo into 512.
    2. Freeze. The networks are used as pretrained, not retrained: about 5,600 prices per training fold would mostly teach them to memorise.
    3. Compress. PCA, fitted on the training fold only, keeps 16 numbers per source.
    4. Combine. LightGBM reads them next to the 141 listing features. Words about price are removed from reviews first, because comments on value are a reaction to the price.

    Where it goes wrong

    Out-of-fold predictions for every listing. Bias above zero means the model over-prices that group.

    GroupListingsMAEBiasWithin ±20%

    The model pulls toward the middle: the cheapest listings are over-priced and the most expensive under-priced. Very low and very high prices often come from things no listing page shows, such as a promotion or a renovation.

    Where it goes next

    Next steps

    Recommendation

    Keep LightGBM on listing features as the engine; grow the data before the networks.

      Deep learning, in order of value

      1. Frozen embeddings into LightGBM (what Stage 7 does). Cheapest way to use text and photos; keep it as the default.
      2. TabPFN v2, a pretrained network for tables under ~10,000 rows: a fair challenger to LightGBM at this data size, and the right neural model to try next.
      3. Fine-tuning a text or image model on price makes sense only with tens of thousands of listings, e.g. after adding more cities.
